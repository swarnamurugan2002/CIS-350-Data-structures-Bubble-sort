What We Have

  • A list of n numbers, in whatever order they happened to arrive in.
  • We're not allowed to just look at them and retype them in order — we need a method that works for a list of any size, that we could hand to a computer.
b

What We Want

  • The exact same numbers, rearranged in place, smallest to largest.
  • Real-world example: a leaderboard of scores, a class roster sorted by GPA, a list of prices sorted low to high. Same problem, different numbers.

2 — How Do We Solve This By Hand?

The general idea, before any code or formal trace

  • Look at the first two numbers. If the left one is bigger than the right one, they're out of order — swap them.
  • Move one step to the right and do the same thing with the next pair. Keep going all the way to the end of the list — that's one pass.
  • Here's the payoff: by the time one pass finishes, the single largest number is guaranteed to have "bubbled" all the way down to the end. It never has to move again.
  • So the next pass only needs to go up to the second-to-last spot — the end is already settled. Keep making passes, each one slightly shorter than the last.
  • Stop when an entire pass happens with no swaps at all — that means nothing is out of order anymore.
?

The General Questions

  • What do we compare? Each pair of side-by-side neighbors, left to right.
  • When do we swap? When the left value is bigger than the right value.
  • When does one pass end? When we reach the last pair in the unsorted portion.
  • When do we stop completely? When a whole pass happens with zero swaps.

3 — IPO

Turning the by-hand idea into Input / Process / Output

InputAn unsorted list of n numbers.
ProcessRepeatedly compare each pair of neighbors, left to right, swapping whenever the left value is bigger. One full left-to-right sweep is a "pass." After each pass, one more number at the end is guaranteed sorted, so the next pass is one step shorter. Stop as soon as a full pass makes zero swaps.
OutputThe same n numbers, rearranged in ascending order, in place.

17 — Why Stop Early?

A one-flag trick that turns a wasted pass into an early finish

  • Before each pass starts, set a flag: swapped = false.
  • Any time a swap actually happens during the pass, set swapped = true.
  • When the pass finishes, check the flag. If swapped is still false, nothing moved this whole pass — the list is already sorted. Stop immediately, even if passes are technically still "left."
  • That's exactly what happened in Pass 3: zero swaps, flag stayed false, so we skipped Pass 4 entirely.
  • Real-world example: if a mostly-sorted list gets one new item added at the end, Bubble Sort with this flag can re-sort it in close to one pass — it doesn't blindly redo all the work.

18 — Complexity

How much work, and why

CaseTimeWhy
BestO(n)the list is already sorted — one pass, zero swaps, the early-exit flag stops everything immediately
AverageO(n²)a typical shuffled list needs roughly n passes, each checking roughly n items
WorstO(n²)the list is in reverse order — every single pass makes the maximum number of swaps
  • Comparisons happen whether or not a swap occurs — in our example, 9 comparisons but only 4 swaps.
  • Extra space is O(1): we only ever need room for one extra value while swapping a pair — nothing scales with n.

19 — Judgment Call: When Does Bubble Sort Make Sense?

O(n²) sounds bad — so why learn it at all?

+

Reasonable to Use

  • Very small lists, where the overhead of a fancier algorithm isn't worth it.
  • Nearly-sorted data — the early-exit flag makes this close to O(n) in practice.
  • Teaching: it's the simplest possible sorting algorithm to trace by hand, which is exactly why it's first.
−

Poor Fit

  • Large, randomly-ordered lists — O(n²) gets slow fast as n grows.
  • Anywhere performance actually matters in production code — later topics (Selection, Quick, Merge, Heap Sort) all beat it on large data.

20 — Check Your Understanding

Answer each one yourself before reading the answer box.

Q1. In the list [1, 4, 2, 5, 8], comparing positions 1 and 2 means comparing which two values?
Answer: 4 and 2 — the values currently stored at those positions.
Q2. After Pass 1 finishes, which position is guaranteed to hold its final, correct value?
Answer: The last position in the unsorted portion — the single largest remaining value always bubbles all the way to the end of a pass.
Q3. True or False: with the early-exit optimization, Bubble Sort always runs all n − 1 passes.
Answer: False. It stops as soon as one full pass makes zero swaps — exactly what happened after Pass 3 in our trace, skipping Pass 4.
Q4. What is the best-case time complexity of Bubble Sort (with the flag), and when does it happen?
Answer: O(n) — when the list is already sorted, the very first pass makes zero swaps and the algorithm stops immediately.

21 — Key Takeaways

Carrying this into Selection Sort next

What We Covered

  1. Bubble Sort repeatedly compares neighbors and swaps when the left is bigger than the right.
  2. Each full pass bubbles the largest remaining value all the way to the end — so each pass can be one step shorter than the last.
  3. A "swapped" flag lets the algorithm stop the moment a pass makes zero swaps, instead of grinding through every remaining pass.
  4. Time complexity is O(n²) in the average and worst case, but O(n) best case with the early-exit flag. Extra space is O(1).
